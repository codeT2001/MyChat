# 整体调优记录（第 1 轮）

> **目标**：整体过一遍代码质量与结构，做一轮**低风险**调优。
> **原则**：不改业务逻辑、不改协议、不改消息 ID / 错误码数值；只做死代码清理、命名/拼写修正、常量收敛、轻微健壮性与可维护性改进。所有改动均"行为等价"或"更健壮"。
> **范围**：`Client/`（Qt6 C++）、`Servers/`（C++：common/GateServer/ChatServer/StatusServer）、`Servers/VerifyServer/`（Node.js）。
> **验证**：Client 全量编译通过（MinGW + Qt6，改动文件单独重编**零告警**）；VerifyServer 通过 `node --check`；服务端本机缺依赖（gRPC/Boost/hiredis/redis++/mysqlcppconn），**未编译**，服务端改动均为可用 grep 复核的机械项。
> **回滚**：本轮改动集中在一次提交内，`git revert <commit>` 即可整体回退；也可按下面清单逐项回退。

## 五、验证方式

```bash
# 客户端：全量编译（本机已通过，改动文件单独重编零告警）
cd Client && cmake --build build --target ChatClient

# VerifyServer：语法检查 + 常量模块自检（本机已通过）
node --check Servers/VerifyServer/server.js
node --check Servers/VerifyServer/redis.js
node --check Servers/VerifyServer/proto.js
node --check Servers/VerifyServer/config.js
node -e "require('./Servers/VerifyServer/constants.js')"

# 服务端：本机缺依赖未编译，需在有 gRPC/Boost/hiredis 的机器上验证
cd Servers && cmake -S . -B build && cmake --build build -j
```

**回归建议**（AGENTS 要求的手工回归）：登录 → 注册（含获取验证码）→ 找回密码 → 搜索加好友 → 收发消息；确认日志无 `LOG_ERROR`，且客户端不再打印报文内容。
