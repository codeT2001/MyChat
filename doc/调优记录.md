# 整体调优记录（第 1 轮）

> **目标**：整体过一遍代码质量与结构，做一轮**低风险**调优。
> **原则**：不改业务逻辑、不改协议、不改消息 ID / 错误码数值；只做死代码清理、命名/拼写修正、常量收敛、轻微健壮性与可维护性改进。所有改动均"行为等价"或"更健壮"。
> **范围**：`Client/`（Qt6 C++）、`Servers/`（C++：common/GateServer/ChatServer/StatusServer）、`Servers/VerifyServer/`（Node.js）。
> **验证**：Client 全量编译通过（MinGW + Qt6，改动文件单独重编**零告警**）；VerifyServer 通过 `node --check`；服务端本机缺依赖（gRPC/Boost/hiredis/redis++/mysqlcppconn），**未编译**，服务端改动均为可用 grep 复核的机械项。
> **回滚**：本轮改动集中在一次提交内，`git revert <commit>` 即可整体回退；也可按下面清单逐项回退。

## 八、P0-2 密码明文存储（服务端）

> 对应 `doc/1.0/chat项目改进建议汇总.md` 的 P0-2，本轮先做**服务端存储侧**。

| # | 文件 | 改动 | 原因 | 风险 |
|---|---|---|---|---|
| S11 | `common/include/chat/password_crypto.h`、`common/src/password_crypto.cpp`（新增） | 新增 `P1::HashPassword()`：`SHA-256(固定盐 + 口令)`，输出定长 64 位小写十六进制 | 提供统一口令摘要；定长 64 正好适配 `user.pwd VARCHAR(64)`，无需改表 | 低 |
| S12 | `common/src/mysql_dao.cpp` | 注册/改密写入 `HashPassword(pwd)` 而非明文；`CheckPassword` 改为按用户名取出摘要后在**进程内做恒定时间比较**（不再用 SQL 的 `pwd = ?`）；`GetUserByName` 不再读取 `pwd` 列 | 库内不存明文、响应/缓存不带密码、比对无时序侧信道（P0-2） | 低（行为等价：用户不存在与口令错误均返回 false） |
| S13 | `common/include/chat/password_crypto.h`、`common/src/password_crypto.cpp` | 新增 `P1::ConstantTimeEquals()`：长度一致时用 OpenSSL `CRYPTO_memcmp` 逐字节不短路比较 | 满足 P0-2「恒定时间比较」要求，避免按字节短路泄漏时序 | 低 |

**说明**
- 未采用可逆的 XOR：可逆意味着库泄漏后仍可还原口令，且变长会超出 `VARCHAR(64)`。改用单向 `SHA-256` + 编译期固定盐（pepper），仍是"简单实现"；生产环境应升级为 bcrypt / argon2id + 逐用户随机盐。
- **升级注意**：历史行仍为明文，哈希后与之不再匹配——旧账号需重新注册/改密（或按新算法回填）。
- 传输侧（HTTP/TCP 明文）属 P0-3，需 TLS，本轮未涉及；响应体经核查本就不含 `pwd`。

**验证**：`cd Servers && cmake --build build -j1` —— 单线程全量编译通过，**零告警**；`HashPassword` 单测（确定性 / 定长 64 / 相邻输入雪崩 61 of 64 位）与 `ConstantTimeEquals` 单测（相等 / 不等 / 长度不同）均通过。

**测试框架**

- `Client/CMakeLists.txt`：`include(CTest)` + `if(BUILD_TESTING) add_subdirectory(tests)`，默认启用，`-DBUILD_TESTING=OFF` 关闭。
- `Client/tests/CMakeLists.txt`：`client_add_test()` 负责组装目标、注入源码树路径（`CHAT_CLIENT_ROOT` / `CHAT_REPO_ROOT`）并注册 CTest；
  使用 **Qt Test**（`Qt6::Test`，随 Qt 提供、零第三方依赖），只编译被测纯逻辑源文件，不建网络/界面。

**测试发现并修复的缺陷**

| 缺陷 | 说明 | 修复 |
|---|---|---|
| 客户端错误码与服务端撞值 | `ERR_NETWORK = 5` 与服务端 `EMAIL_NOT_MATCH = 5` 同值；`static_cast<ErrorCodes>(5)` 命中本地网络错误分支 → 找回密码姓名邮箱不匹配时提示「网络异常」；其余 6/7/8/9/10 只显示「请求失败（错误码 N）」 | 客户端 `ErrorCodes` 补齐并逐项对齐服务端；本地码挪到 5000+；补 6 条文案；契约测试钉住 |
| 中文长消息被服务端断连 | 客户端按 UTF-16 字符数分批（上限 1024），中文消息 UTF-8 后可达 3KB+，且 `msg_id` 包装另算 → 超过服务端 2048 字节直接 `abort` | 改为 UTF-8 字节 + 包装开销累计，空批次不发；上限常量与用例一起固定 |
| 认证通知 `action=0` 被当作拒绝 | 客户端 `obj.value("action").toInt(ACCEPT)` 对「键存在且值为 0」返回 0 → 既不建好友也不提示同意；服务端 `ResolvePeerAuthAction` 对 0/未知按同意兼容 | `NormalizePeerAction`：只有 2 才拒绝，其余按同意 |
| 文件大小显示错档 | `else if (size < 1024 * 1224)` 笔误，1MB~1.2MB 落入 KB 分支 | 改 `1024 * 1024`，并抽到 `Utils::FormatFileSize` 纳入用例 |
| 发送日志泄露 token | `TcpManager::Send` 打印完整 body；`HttpManager` 打印完整响应 | 只打印长度；超服务端上限告警 |
| `AddFriend(AcceptPeerInfo)` 空指针崩溃 | 另一个重载判了空，这个重载直接 `make_shared<FriendInfo>(auth_info)` 解引用 | 增加空指针守卫 + 用例 |

## 十九、界面交互测试（离屏点击登录框与主面板）

> 第十八节只能覆盖纯逻辑；「手工点界面」里的本地分支（校验提示、密码可见性、切页、搜索覆盖页、
> 点击会话进入聊天）同样可以用 Qt Test 自动化，且不需要显示器与服务端。

**做法**

- 用 `QTest::mouseClick` / `keyClick` / `keyClicks` 向控件派发**真实鼠标/键盘事件**，
  用 `findChild<T*>("对象名")` 按 `.ui` 里的对象名定位控件，用 `QSignalSpy` 断言跳转/发送信号；
- 测试进程自行 `show()` 窗口并等待 expose，CTest 以 `QT_QPA_PLATFORM=offscreen` 运行（无显示器可用）；
- 数据由内存中的 `UserManager` 预置（本人资料 + 一个带历史消息的好友），不连服务端。

**新增目标**

| 可执行 | 用例数 | 覆盖 |
|---|---|---|
| `test_ui_widgets` | 10 | 登录框：空输入 / 非法用户名 / 短密码 → 对应提示且按钮保持可点；失焦校验后提示随合法输入清除；密码可见性两次切换（Password ↔ Normal）；注册 / 忘记密码按钮发出跳转信号；`OnLoginError` 回显文案并恢复按钮。验证码倒计时：点击后禁用、文本 `60s`、1 秒后变 `59s`。输入框：回车发 `SigSend`，Shift+回车不发送。可点击标签：状态切换 + `clicked` 计数 |
| `test_mainpanel` | 4 | 侧边栏聊天/通讯录互斥切页（`QStackedWidget` 当前页 + 按钮选中态）；搜索框输入后进入搜索覆盖页；点击列表外空白退出搜索、清空输入并回到原页；点击会话条目进入聊天页且 `ChatPage::GetCurrentUid()` 为对应好友 |

**构建依赖处理**

- `test_mainpanel` 会拉起会话列表、聊天页、通讯录、资料页等几乎全部 UI 组件，因此直接复用
  `Client/src/*.cpp`（排除 `main.cpp` / `mainwindow.cpp`）与 `ui/*.ui` 全量（AUTOUIC/AUTOMOC/AUTORCC）；
- `inc/*.h` 全量交给 AUTOMOC，但必须排除 `mainwindow.h`——其实现未纳入，否则生成 `moc_mainwindow.cpp`
  会在链接期引用未定义的 `MainWindow` 符号；
- 只给两个 UI 目标链接 `Qt6::Widgets` + `Qt6::Network`，其余纯逻辑目标保持 `Core/Gui` 最小依赖。

**边界（仍需手工/联调）**

- 真实网络往返不在此层：登录 → GateServer 分配节点 → TCP 登录 → 跨节点通知 → 收发消息；
- 拖拽图片/文件、真实搜索结果渲染等依赖外部数据的交互，仍需起服务端后手工冒烟；
- 离屏模式可能出现 `QFontDatabase` 找不到字体目录的 QWARN，不影响断言。

**验证**：`cmake --build build -j4 && ctest --test-dir build --output-on-failure` ——
8 个测试、**59 个用例**全部通过（界面测试约 1.2s + 0.6s）。失败详情同样落在 `build/tests/reports/`。
