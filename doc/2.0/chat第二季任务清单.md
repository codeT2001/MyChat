# Chat 项目第二季任务清单

> 来源：[C++全栈聊天项目实战 · 语雀](https://www.yuque.com/lianlianfengchen-cvvh2/dz8xhn)（作者：恋恋风辰zack）
> 第一季已完成，对应本仓库 `doc/1.0/` 的实现内容。
> 下表按语雀「第二季」目录顺序整理，只保留标题 + 简要说明；勾选表示已实现。

## 第二季任务

- [ ] **1. 文件传输原理** — 讲清文件/图片如何分块并在 TCP 上传输：定义文件元信息（文件名、大小、哈希）与二进制分片协议，扩展当前只有 JSON body 的帧结构。
- [ ] **2. 分布式锁设计思路** — 用 Redis（SETNX + 过期/续期）实现分布式锁，保证多 ChatServer 节点下同一用户/资源的并发互斥（顶号、资源上传等）。
- [ ] **3. 单服务器踢人逻辑实现** — 同节点内新登录顶掉旧会话：`UserManager` 找到同 uid 旧 session，推送 `NOTIFY_KICK` 后关闭连接；消息号已有，需补完整流程与客户端处理。
- [ ] **4. 跨服踢人逻辑实现** — 用户在其他 ChatServer 节点时，经 gRPC `ChatService` 通知对端踢人，配合 Redis 的 user→server 映射定位目标节点。
- [ ] **5. 心跳检测实现** — 客户端定时 PING 已具备，服务端需补超时检测：定时清理长时间无心跳的死连接。
- [ ] **6. 实现头像编辑框** — 客户端个人资料头像裁剪/上传 UI，复用文件传输通道保存头像。
- [ ] **7. 聊天信息存储方案** — 聊天消息落库（MySQL 消息表/会话表）：历史消息分页拉取、离线消息补发；当前文本只做转发、未持久化。
- [ ] **8. 断点续传** — 大文件传输的偏移量记录与续传协议（offset + 分片确认）。
- [ ] **9. 异步回调和续传持久化** — 发送端异步 ack 回调，并把续传状态（已传分片）持久化到 Redis/DB。
- [ ] **10. 实现资源断点下载** — 资源（图片/文件）下载支持断点（Range），客户端展示下载进度。
- [ ] **11. 多媒体信息传输** — 图片/语音/视频等消息类型在协议层贯通（目前只有文本打通，见 `Client/README.md` 已知问题）。
- [ ] **12. 设计拥塞窗口提升发送效率** — 滑动窗口/拥塞控制：批量发送分片、按 ack 推进窗口，避免逐片等待。
- [ ] **13. 分布式事务死锁分析** — 好友、资源等多表跨服务操作的加锁顺序与死锁排查。
- [ ] **14. 聊天资源续传和进度显示** — 客户端续传逻辑 + 进度条 UI（结合第 8/10 项）。
- [ ] **15. 粘包问题引发的血案** — TCP 粘包/半包处理：定长帧头 + 缓冲状态机（本仓库已把帧头长度字段改为 4 字节，见 `Servers/ChatServer/src/csession.cpp`）。
- [ ] **16. rpc通知客户端异步下载聊天图片** — 服务端经 gRPC 触发对端节点，向在线客户端推送「有新图片」通知，客户端异步下载。
- [ ] **17. 用户登录加载聊天资源** — 登录后拉取历史消息、头像、图片等资源并渲染。
- [ ] **18. webrtc的coturn服务搭建** — 部署 STUN/TURN（coturn）用于 NAT 穿透。
- [ ] **19. WebRTC 1v1 视频通话技术方案（Node.js + WebSocket）** — 信令服务 + WebRTC 媒体协商，实现一对一视频通话。

## 建议推进顺序

1. 帧层与可靠性：15 粘包 → 5 心跳超时 → 3/4 踢人（单服/跨服）。
2. 文件与多媒体基础能力：1 文件传输原理 → 8/10 断点续传与下载 → 9/14 续传持久化与进度 → 11 多媒体传输 → 12 拥塞窗口。
3. 数据与并发：7 聊天信息存储 → 2 分布式锁 → 13 分布式事务死锁。
4. 音视频与资源加载：16/17 资源通知与登录加载 → 18 coturn → 19 WebRTC 1v1。
